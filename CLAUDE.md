# dns — working notes

Full reference: **README.md** (CLI, solvers, BCs, measured anchors). Design history: `docs/archive/`.
Specs: `docs/nscbc.md`, `docs/validation.md`, `docs/viewer-format.md`, `docs/channel.md`, `docs/scene.md`, `docs/rans.md`.

## Ground rules

- ONE solver binary: `build/dns <flow|tgv|hit|channel|conv|bench|prop>`. The old 15 apps are gone. `dns --help` / `dns <sub> --help` are authoritative — read them, don't guess flags.
- `dns-ui` is the second binary and the only exception: scene editor, run cockpit and live viewer. It links `dns_core` ONLY — never `dns_gpu`, never a solver. It RUNS a case by spawning `dns` as a child process, and WATCHES it by mapping the shared-memory segment that run publishes. Keep it that way: the moment it links the GPU it stops being a front end. `docs/ui.md`.
- Live results are shared memory, not files: `--emit shm` (`src/dns/shmframes.hpp`) publishes planes, the mask and the 3D volumes under a SEQLOCK — writer bumps odd, copies, bumps even. The solver NEVER blocks on a viewer; a dead viewer cannot slow a run. A reader copies between two equal even reads and discards a torn one. Volumes are capped at 512 MB; over budget the run publishes planes only.
- `--dry-run` validates + prints the resolved case (and the DNS/LES label) without touching GPU or filesystem. Use it before every real run.
- Parsing is strict: unknown/missing/non-numeric flag = hard error. Exit codes: 0 ok, 1 CLI, 2 config, 3 input, 4 output, 5 no GPU, 6 resource, 7 numerical, 8 non-convergence, 77 skipped.
- `main` = Parse → Validate → Acquire → Run. Phases 1-2 touch neither filesystem nor GPU; phase 3 creates every output before the first `hipMalloc`.
- `std::expected` for anything a USER can cause; `assert` only for what a PROGRAMMER can cause (legitimate only if the validator makes it unreachable). Release is the build that runs — never assert-as-input-guard.
- Build: `build/`, CMake+ninja, **Release always** (never RelWithDebInfo — disk space), one GPU backend option ON. Tests: ctest; GPU tests skip (rc 77) without a device. Always run tests with a timeout.
- TWO GPU backends, ONE set of sources. `src/dns/gpu/*.hip` is HIP; `DNS_WITH_CUDA=ON` compiles those SAME files as CUDA through the header shim in `src/compat/cuda` (hip*→cuda*, hipfft→cuFFT, rocprim→CUB/thrust; read its README). Never fork a solver per backend, and never add a `#if DNS_WITH_CUDA` outside the shim — a HIP call the shim lacks is a build error ON PURPOSE: extend the shim in the same commit. `DNS_WITH_GPU` (not `DNS_WITH_HIP`) is the "a GPU backend exists" macro in app code. The backend's NAME (`gpu::backendName`, the `backend=` provenance field) is `DNS_GPU_BACKEND_NAME`, defined by the CMake backend branch -- not an `#if` in a header.
- GPU arch is AUTO-DETECTED for both (`CMAKE_HIP_ARCHITECTURES` / `CMAKE_CUDA_ARCHITECTURES`); wrong HIP arch = `getStatFunc` assertion. CUDA needs nvcc with `-std=c++23` (configure compiles `<expected>` to check) and CMake ≥ 4.3 still needs the CUDA23 dialect flag taught to it, which the CUDA branch does.
- Long runs: `run_in_background`, act on the completion notification. No Monitor/sleep/until polling loops.
- Artifacts when asked to publish: dark mode; videos colormapped with curl and |velocity|.

## Layering

`cli/config` (pure parse+validate; also `dns/scene`, `dns/remap`, `dns/sgs`, `dns/rans`) → `bodies/geometry` (sdf + cut sampling; also `dns/curvmesh`, `dns/framemap`, `dns/walldist`, the FP64 oracle `dns/rans_channel1d`) → `gpu/{tunnel,bodyforce,les,rans,cutpoisson,cutflux,derived,comp_channel,comp_conv}` → `gpu/runner_{incomp,comp,channel,conv}` → `output` (RunOutput, the one artefact sink). Preserve it; validated physics constants live at their definitions with the measured bracket recorded.

## Invariants you must not break

- **2D is `nz == 1`, not a code path.** Periodic wrap makes every z-stencil term cancel identically; w stays exactly 0. Never branch z-terms out. Only solvers special-case degenerate axes (hipfftPlan2d, DCT skip, open box faces). Only z may be degenerate; `hz = 1` is validator-enforced. Keep the `*2d` parity tests green.
- **Ghost view is diffusion-only.** `gpu/ghostfill.*` mirror values must never reach convection or leak into the state — measured energy injection. Ghost faces have zero aperture.
- **Tunnel lateral walls are free-slip/Neumann.** Do not reintroduce the Dirichlet `u=uInf` far field (clamped sheared flow, painted a wall vortex sheet).
- **Open/lateral BCs must leave normal velocity free.** Relaxing v→0 or u→uInf laterally is a wall in disguise. In the open tunnel, lateral faces are slaved once per stage BEFORE projection; the post-projection refresh is `refreshOnly=true` (re-slaving broke div u by ~150×).
- **The compressible RK stage is FUSED: there is no materialized rhs.** `kCompStage`/`kCompStageCurv` write `out = ca*a + cb*b + cr*(-div F)` in one pass (`StageCombine`, `gpu/comp.hpp`), which is why the solver holds two stage buffers instead of three. Two rules follow. (1) The stage OUTPUT must never alias `cmb.a`: a boundary rhs hook runs as a second kernel over the same cells and re-reads `a`, which an aliased output has already overwritten — that broke every NSCBC check once. Stage 3 writes `q1_` and swaps. (2) Because the state buffers are swapped, no caller may hold a raw device pointer into the state across a step.
- **NSCBC is an RHS overwrite** (`setRhsHook`), never a state overwrite — that is why it avoids the deleted `comp_bc`'s acoustic transients. Inflow relax must stay stiff (`etaIn 100`) WHEN THERE IS A FREESTREAM TO SAG -- that is what `--nscbc-etain` is now for, and 100 stays the default. With no freestream (a static rotor) it is pure acoustic mirror: measured 0.81 amplitude back on a normal wave, and 11% of a radial pulse's energy kept in an open box against 0.04% at etaIn 0.5. In that geometry etaIn is worth a factor of 280 and the transverse coefficient is worth 3% -- do not reach for the transverse term first. Outflow needs the Yoo-Im transverse term (`--nscbc-beta`, default 0.5; 1.0 diverges).
- **`--nscbc-beta` is a constant and the right coefficient is not.** For an outgoing wave at incidence theta the exact incoming amplitude needs `beta_opt = cos t/(1 + cos t)`, of which 0.5 is only the normal-incidence limit; the measured optimum falls to 0.2 at 75 deg. `--nscbc-abc adaptive|modal` reads theta off the face itself (`Tp/Lout = (1 - cos t)/cos t`, both already computed) and is then EXACT at every angle rather than through O(t^2) -- the Engquist-Majda symbol summed, not truncated, with no auxiliary time history. Normal incidence is bit-for-bit unchanged. The two differ ONLY in where the ratio is formed and that is the point: `adaptive` is per face cell, needs no plane, and works on EVERY open face and any mesh; `modal` is per transverse DCT-II mode of the x-hi plane, which is the exact eigenbasis only when the laterals are free-slip walls, and is rejected (never ignored) with `--open`, `--stretch`, `--focal`, `--ogrid` or `--body floor`. Measured at 75 deg: adaptive +34% vs the best hand-tuned constant, modal +1.0% -- a pointwise ratio reads an AVERAGE angle out of a superposition, the DCT separates it. `docs/nscbc.md`, test `gpu_nscbc_order`.
- **Two absorption results published 2026-07-28 were measurement artifacts and are retracted** (`docs/nscbc.md`). A whole-grid vorticity scan differenced the outflow row against the inflow row across the periodic wrap and made the face look like a vorticity source (peak 1.51 at i = nx-1; 0.006 with two cells peeled). And an oblique reflection has a WINDOW -- the tilted band has not cleared until its most-upstream point is out, while the reflection starts leaving the far face after one box length -- which in a square box has no solution past ~45 deg. Anything measuring a boundary must state where the peak sits and show the number is flat in time. Note the correct fix is a NON-WRAPPING difference, not a margin: peeling cells off also peels off where a boundary-made sheet would live. Measured that way the residual vorticity is 0.22 of the incident scale and its peak is in the x-interior against the free-slip y wall -- the outflow row lays down no sheet, so the "L3 = u dv/dn vanishes at u = 0" argument is refuted, not merely unproven.
- **What the face cannot absorb is the sink's, not the closure's** (measured 2026-07-30, `gpu_comp_sink`, docs/nscbc.md "Small scales and the strip hand-off"). The central flux transports nothing at the mesh scale (group velocity `c cos(kh)`, <= 0 from 4 cells/wavelength down): a packet released against the outflow strands 2%/23%/69%/98% of its energy over kh = pi/4..pi and a 4dx vortical patch simply PARKS. `--nscbc-sink N` (+ `--nscbc-sink-amp`, (0,2] = the SSP-RK3 bound) is the explicit remedy: D4/sin^4 selective damping in conservative flux form, banded inside the open faces, additive rhs UNDER the NSCBC overwrite. Exactly zero on constant and linear fields -- no freestream reference, so unlike the strip it cannot sag, wall, or eat the near field (resolved vortex mid-band: sink keeps 0.9999, strip 16 keeps 0.6813). It deliberately does NOT fix the resolved-scale inflow mirror (0.810 -> 0.802) -- that is etaIn's or the strip's. **ON BY DEFAULT (16, amp 1) for `--far nscbc` wherever defined** -- uniform mesh, whole faces, band fits twice per open axis; measured free (Re60 nscbc cd +0.003%). `--nscbc-sink 0` is the bare boundary bit-for-bit; the default silently stays off on `--stretch`/`--focal`/`--ogrid`/`--body floor` (a default that does not apply is absence), while an EXPLICIT sink there is rejected, never ignored. This default is the ONE deliberate exception to "no absorbing band by default": it has no freestream reference, so none of the sponge rule's reasons apply -- do not cite it to justify a sponge.
- **The lateral relax writes vorticity in proportion to its rate** (measured 2026-07-30, `gpu_nscbc_order`). Bare `--open` laterals are 4x WORSE than free-slip walls on the 45-deg ridge (0.80 vs 0.22 of incident scale, peak ON the lateral face): the incoming relax `etaLat c/L (v_t - tgt)` is itself the source, scaling 0.20/0.80/2.16 over etaLat 0.05/0.25/1.0 -- "a stiff lateral clamp is a wall in disguise", now a number. The working open-box configuration is sink 16 + etaLat 0.05: residual 0.032, seven times below the walls baseline -- and it IS now what plain `--open` resolves to (both are the defaults; etaLat was 0.25). The vortex-on-face transparency rig is etaLat-insensitive (0.026-0.027) and the open Re60 cylinder cd moved -0.003%, so the flip costs nothing measured. The walls' own 0.22 is resolved-scale vorticity parked in a quiescent box -- nothing local removes it, a freestream advects it out.
- **Two boundary "fixes" were prototyped, measured inert, and dropped -- do not re-derive them** (docs/nscbc.md). `--nscbc-order 2` (3-point one-sided dn()): every reflected-energy figure moved in the 4th decimal; the closure owns the oblique error, not the stencil. An outflow backflow blend (etaOut on x-hi L2/L3/L4): residual unchanged to the 4th decimal even under 4x-freestream backflow -- the lambda = u amplitudes are proportional to un and shut off smoothly through a stagnation on their own (`backflowVortexResidual` pins it).
- **The inflow acoustic mirror is the sag guard's own** (measured 2026-07-30, `gpu_nscbc_absorb`). `--nscbc-etain-shear` puts the lambda = u family (entropy L2, shear L3/L4) on its own rate (default: follow etaIn, bit-identical); softening it 400x moves R_inflow by 0.1% -- a normal wave reflects off the `u = uInf` clamp ITSELF, so only `--nscbc-etain` or the strip can fix the mirror. What the family rate owns is the vorticity the face writes under vortical load (0.0069 -> 0.0050 of core scale, 100 -> 0.25); its real customer is turbulent inflow, where L3/L4 at 100 would clamp every injected eddy.
- **Sponge is NEVER a default — anywhere, any physics, any mode.** `--far sponge` is an escape hatch / explicit fallback ONLY: it relaxes the freestream in a boundary band that eats the near field. The compressible default is `--far nscbc` (physical characteristic boundary). If a run needs sponge, the user asks for it by name; never reach for it silently. Same for the struct/runner defaults — keep them off sponge.
- **`--far nscbc` alone only to Re800**; beyond, add `--nscbc-sink 16` (scale-selective, preferred) or `--nscbc-strip ~ny/64` (freestream sponge) — the validator enforces one of the two.
- `--pot` off, or Q=0 ∧ a=0, is bit-identical (test-pinned). `csLes == 0` is bit-for-bit molecular DNS.
- Deterministic iteration/order wherever output depends on it.
- **The editor covers BOTH `dns flow` and `dns conv`, and both physics of each.** `DocState::sub` picks the subcommand; the panels gate wholesale on it (a conv case has no body, so the Geometry region says so rather than offering a picker every choice of which the validator rejects). Conv's SI face is layer height + temperature drop + material -> Ra DERIVED, the same idiom as body size + freestream -> Re. `dns-ui --check` carries a COMMAND ROUND-TRIP GATE: the exported argv is fed back through the real `cli::parse` + `validate` and the resolved case must match the one the document built, at the 4-significant-digit precision the printed command actually carries. A flag the editor forgets, doubles or misnames fails there.
- The self-check owns `/dev/shm/dns_uicheck*` and clears them at BOTH ends, and asserts nothing outlived it. It used to leak one every run (a second run was stopped before it was live, so it died to SIGKILL and never unlinked), which made the NEXT `--check` fail ~1 in 3 on an unrelated live-bridge assertion. A stop issued before a run reaches its time loop is still not clean -- documented in `docs/ui.md`, not fixed.
- **The editor owns no physics.** Where it needs a solver rule it CALLS it: `dns::sceneObjectBox`, `sceneBoxInside`, `needs3d`, `validSceneName`, `defaultSceneName`, `checkSceneNames` live in `dns/scene.*` and `parseScene`/`buildSceneGeometry` are routed through the same functions. Never restate a rule in `src/ui/` — move it, and refactor the core's own caller onto it in the same commit. The editor's scene is DEFINED as `parseScene(sceneToml())`, so a file it writes is one the CLI accepts.

## Temperature (compressible)

- The gas is air: diatomic and **calorically perfect**, gamma = 1.4 FIXED. The vibrational mode is frozen below ~600 K; gamma(T) is deliberately not modelled. `dns/transport.hpp` (`dns::Transport`) is the ONE gas object (gamma, R, Pr, viscosity law) and the only route by which mu and kappa reach anything — `Comp::tr`, `DeviceComp::transport()`, `gpu::viscView()`. Do not reintroduce a scalar mu/kappa pair.
- Every thermal knob is OFF by default and a run naming none of them is bit-for-bit the pre-thermal solver: that is what keeps the measured cd/cl anchors valid. `--visc sutherland` (mu(T), kappa(T) = mu cp/Pr), `--tinf K` (the ONLY dimensional anchor, needed because Sutherland's 110.4 K is not scale-free; box T carries the scale 1/(gamma M^2)), `--prandtl`, `--wall adiabatic|isothermal` + `--twall RATIO` (body surface), `--nscbc-tinflow`.
- Sutherland is evaluated ONCE PER FACE on the face-average temperature — the same average the Fourier flux uses — so both sides of a face see one consistent (mu, kappa) pair and the scheme stays exactly conservative. Never per cell.
- **The diffusive dt limit is thermal, not viscous.** `0.25 h^2 rho_min / (mu_max * max(1, gamma/Pr))`: the energy equation carries `kappa/(rho cv) = gamma nu / Pr`, 1.94x the momentum nu for air. The old momentum-only bound overestimated dt by that factor. Compressible runs are essentially always acoustically limited, so it costs nothing in practice. With Sutherland on, `mu_max = mu(max T)` from ONE max-T reduction — valid only because the law is monotone in T.
- Wall heat flux rides the same surface tally as cd/cl (`qw` column, positive = fluid into body). It is the CONDUCTION term, so an adiabatic wall reports exactly zero.
- `--temp` adds a THIRD frame channel (`temp` = T - Tinf, diverging) to the compressible flow and O-grid runners. Off by default on purpose: it changes what every artefact of a run contains, and a thermal knob must not do that silently. `conv` always emits it — there, temperature IS the physics.

## Gravity and buoyancy (`dns conv`)

- **Gravity exists in exactly one place and only there.** `gpu/comp_conv.hpp`'s `addGravityY` is the whole of it: `my += cr*(-g rho)`, `E += cr*(-g my)` on the fluid rows, through `setRhsHook` like the channel body force, so it rides SSP-RK3 and the FUSED stage kernel is untouched. Every other subcommand runs at g = 0 and is bit-for-bit unaffected. Do not add a second buoyancy term anywhere.
- **There is no Boussinesq approximation and there must not be one.** The solver is fully compressible; density already responds to T through the EOS, so buoyancy IS rho(T) g. A Boussinesq branch would be a second, disagreeing physics.
- **The IC is a hydrostatic equilibrium, not a uniform box.** `convIC` integrates `dp/dy = -rho g` through the linear conduction profile (exactly `p = pRef (T/Tref)^(-g/(R a))`). Starting uniform would drop the layer and ring the box acoustically for the whole run. Pinned in `conv_config` to 1e-4 relative.
- **Two temperature scales, deliberately different, do not "unify" them.** Gravity carries its own adiabatic gradient `g/cp`, so only the SUPERADIABATIC excess `dTsuper = dtemp - (g/cp) H` drives convection (Schwarzschild). `--rayleigh` is on `dTsuper` (hence critical Ra = the textbook ~1708); the reported Nusselt numbers are on the FULL imposed drop (hence quiescent conduction = exactly Nu = 1). A subadiabatic layer is a config error, rejected by name — never run to a null result.
- **`--mach` is what sets gravity** (`g = M^2 gamma / dtemp`), not an incidental knob. The adiabatic fraction is `M^2 (gamma-1)/dtemp^2`: 10% at the defaults, 1.6% at `--mach 0.02`. Lower M = closer to Boussinesq = more steps per free-fall time.
- Measured 2026-07-26, 2D Pr 0.72 coarse grids (`gpu_conv`, NOT converged Nusselt numbers): Ra 1000 → Nu 1.00 at rest; Ra 2e4 → Nu 3.00; Ra 5e4 → Nu 3.81 (~Ra^0.28). Wall and interior Nu agree to <5% — that agreement IS the heat balance closing, so a spread means a bug, not scatter.
- **`conv` has TWO physics and they are two MODELS, not two solvers.** `--physics compressible` (default) = `gpu/comp_conv` + `runner_conv`, density from the EOS, acoustic dt, stratified. `--physics incompressible` = `gpu/boussinesq` + `runner_rb`, divergence-free, no sound speed, no adiabatic gradient, free-fall scaling (H = dT = g*alpha = 1, nu = sqrt(Pr/Ra), kappa = 1/sqrt(Ra Pr), t_ff = 1). Knobs that only mean something against a sound speed (`--mach`, `--dtemp`, `--visc sutherland`, `--tinf`) are REJECTED on the Boussinesq branch, never ignored.
- **The cross-validation is the load-bearing test.** The two branches share the case derivation and the output sink and NO physics code. Ra 5e4 2D, matched windows: compressible Nu 3.79, Boussinesq 3.97 (4.6%). Pinned in `gpu_rb`, banded at 15%. If you touch buoyancy, a wall condition or the temperature transport in either branch, that agreement is what tells you which one you broke.
- **`--sides periodic|closed` is a BC on the LATERAL faces, and closed is a different experiment, not a variation.** Closed = a sealed cavity: x, and z only when nz > 1, become no-slip **ADIABATIC** walls on the plates' own one-cell ghost ring (`kRbWallSide`, `kConvWallSide`, both indexed by `internal::sideGhostPair`, axis order y→x→z so a corner ghost is the diagonal reflection). The grid gains two cells per closed axis and the FLUID extent, spacing and `--n`/`--nz` meaning do not move (`nxInterior`/`nzInterior`; `sideGhostX/Z` in `gpu/index.hpp` is the ONE definition of the offset, read by the kernels AND the host plane divisors -- if those two disagree every plane mean is wrong). Adiabatic on purpose: the drop across the PLATES is the experiment, so a side copies T and p (hence rho and E) and antimirrors momentum. The Boussinesq branch also switches the pressure problem to `PoissonBc::NeumannBox` -- a closed side is zero-flux for p exactly as a plate is, so no mixed transform was needed. Periodic is bit-for-bit the pre-flag solver on all four paths (2D/3D x incomp/comp), verified against the HEAD build, and the ICs' lateral trip envelope is branched so an open axis keeps the periodic factor verbatim. Measured 2026-07-26, Ra 5e4 aspect 2: 2D Bouss 3.97 -> 3.65, 2D comp 3.81 -> 3.38, 3D Bouss 4.20 -> 3.58 -- Nu is BELOW the periodic value (braked corners, roll count fixed by aspect) and is a cavity number to which neither 1708 nor the Ra-Nu scaling applies. Subcritical closed stays at rest (Nu 1.00) -- that is the check that the wall fill forces nothing; the heat balance closing is the check that the sides leak nothing. BOTH gpu tests carry a 3D cavity: closing z is a second ghost ring, a third DCT axis and the z wall pass's corner ghosts, and a wrong-axis plan there leaves every 2D case green (the `gpu_poisson_wally` lesson).
- `PoissonBc::PeriodicXZWallY` (`gpu/poisson.hip`) is FFT in x/z + an exact TRIDIAGONAL solve in y, deliberately NOT a mixed DCT: y needs no transform, so it stays exact for any ny and the Makhoul machinery is not extended to a mixed-transform case. `hipfftPlanMany` IGNORES istride/idist when inembed is null and silently transforms the wrong axis -- that cost a debug cycle (2D green, every 3D case wrong). Test: `gpu_poisson_wally`.
- **The Boussinesq IC MUST break the up-down symmetry, and `rbIC`'s `cos(pi y/H)` factor is what does it.** With plates at +/- dT/2 about Tref = 0 the equations are exactly equivariant under (y -> H-y, T -> -T, v -> -v); a trip respecting that symmetry leaves the run locked in the symmetric state forever. Measured 2026-07-26: the two wall Nusselt numbers then agreed to SIX DIGITS at every instant -- which looks like a perfect heat balance and is actually the balance being unfalsifiable. `gpu_rb` pins BOTH that the time means agree (balance closes) and that the instantaneous values differ (not locked); the first check is vacuous without the second. The compressible branch needs no such term -- its hydrostatic stratification breaks the symmetry physically.
- **`--hot-patch F` heats a centred fraction of the FLOOR only** (both branches; surround at the lid temperature). `F = 1` is bit-for-bit the flagless run and `gpu_rb` compares the stats files byte-for-byte. In 3D F is a SIDE fraction, so the area is F^2 (F = 0.577 is a third of the area); at nz == 1 it is the middle strip in x. Below 1 this is NOT classical RB: no 1D conduction state, the 1708 onset does not apply, and `nuBot` is a net floor-area-averaged flux (the cold surround absorbs heat), not a Nusselt number -- the validator warns in those words. The wall-gradient Nu is built from plane averages, so its pinned value must be the AREA-MEAN wall temperature (`rbPatchAreaFraction` / `convPatchAreaFraction`, counted in cells), not Tbot.
- The progress line in `runner_{channel,conv,rb,comp,ogrid}` needs its OWN counter (`lastPrint`). Sharing `lastLog` with the CSV cadence made `steps - lastLog >= 10*statsEvery` unreachable -- lastLog resets every statsEvery steps -- so the line only ever printed at tEnd and dns-ui's live plots stayed empty for the whole run. Fixed in channel/conv/rb 2026-07-26 and in comp/ogrid (which still had it) when all five moved onto `internal::StatsCadence` (`gpu/internal/run_loop.hpp`), the one place the two counters now live.
- Interior-only diagnostics on the Boussinesq path: the antimirrored ghost rows carry a legitimately huge divergence (~0.5 against an interior 3e-6), so `maxDiv` zeroes them first (`zeroYGhostRows`). A whole-grid max reports the mirror, not the projection.
- The domain y walls in `gpu/comp_far.hip` are still hardcoded ADIABATIC mirrors (`E[c] = E[s]`). Only `DeviceConvWall` (conv) and `DeviceChannelWall` (channel) carry wall temperatures; `--wall isothermal`/`--twall` on `flow` is the BODY surface, never the box.

## Rotors — moving geometry (`dns flow --rotor-mach`)

- **`--rotor-mach` is the ONE switch, and 0 is bit-for-bit the static solver.** Geometry built once, wall at rest, stats file with the columns it always had. Every other rotor flag is rejected without it. That is what keeps the measured cd/cl anchors valid. Compressible `flow` only — the moving wall IS the compressible ghost wall and there is no incompressible counterpart.
- **The moving wall is one added term, and it is the SAME image the isothermal thermal wall uses.** `u_ghost = (1+a) u_wall - a u_sample` with `a = gscale = dw/dsmp` (`gpu/comp_ghost.hip` `kGhostFill`): the resting mirror at `u_wall = 0`, the familiar `2 u_wall - u_sample` at `a = 1`. The resting branch is kept VERBATIM under `if (uw)` rather than folded into the general form — `a*a*(ui*ui)` and `(a*ui)*(a*ui)` are not the same float. Without the term a blade is a rotating HOLE: wake, no thrust.
- **`comp_ghost` owns no motion model.** It takes a `GhostWallMotion` callable returning `GhostWallKinematics{u, a}` and samples it once per ghost at the FOOT OF THE WALL NORMAL (`a` feeds the pressure image). A rotor supplies `gpu::rotorWallMotion` (`dns::rotorWallVelocity` + `dns::rotorWallAcceleration`); a pitching or translating body would supply its own. Never put `omega` in that module.
- **Azimuth is COMPUTED, never accumulated**: `theta = omega * t` from the step's own `t`, bin index integer mod bins. That, and only that, is why a revolution closes exactly after thousands of them. An integrated angle drifts off the bin grid.
- **Geometry is fixed within a STEP, not within a stage.** Measured: at an acoustic dt the tip moves ~0.1 of a fine cell per step, three orders below the wall discretization. A per-stage swap triples the copies to chase it. Do not "fix" this.
- **The azimuth table is HOST memory, replayed into ONE set of device buffers.** `gpu/rotortable.*` classifies every bin up front (threaded; `classifyCompGhost` is pure host and reentrant), `DeviceCompGhost::fromTables` sizes the buffers for the largest bin, `load()` swaps one in. A bin change is a copy, never an allocation, and `load()` REFUSES a table past the capacity rather than truncating. Measured on the 2D diamond at 192²: 0.10 swaps per step, exactly `bins` swaps per revolution.
- **`--blade-thicken` CHANGES THE BODY and must be reported like the DNS/LES label.** `sdf - C*h_fine` is exactly a Minkowski sum with a ball, so the field stays a true distance and convex edges round rather than distort. It exists because the ghost wall needs a mirror band >= 2 cells per side (`gpu/comp_ghost.hpp`), so a blade under 4 fine cells thick has its two surfaces reading through each other. `casegeom` applies it (through `rotorSdf` at theta 0, the ONE definition) so the sdf the ghost wall reads and the cut `qRef` measures are the same body; the runner then turns with `thicken = 0` because dilating and turning commute — a rotation is an isometry.
- **The resolution gate is MEASURED, not asserted**: the run reports the deep-solid cell count over all bins and warns when it is 0. The validator cannot know it — it may not open the mesh.
- **`--rotor-mach` is quoted on the NOMINAL tip radius `D/2`**, because that is all `validate()` can know without the filesystem. A body reaching further (lens, scene, overhanging mesh) has a faster real tip; the runner measures it from the classified interface faces and STOPS with the corrected number. Measured: `--body lens --aspect 4 --rotor-mach 0.4` is a real tip Mach of 1.61 and used to just diverge.
- **A rotor is exempt from the `--focal` mesh-body rejection, and the reason is not a loophole**: its swept volume is bounded by the placement cube from `--dr` and `--rotor-span` alone (span capped at 0.5), so the plateau derivation needs no mesh AABB. `rotorSweptBox` is the flags-only form for the validator; `rotorSweepBounds` is the exact measured form for the run.
- Torque rides the SAME staged FP64 face values as drag (`kBodyMoment` reads spans 0..2 of `facc_` and writes 4..6), so torque and drag cannot disagree about which faces are the body. Face positions travel in the tables (`fpos`) rather than being recomputed, because on a focal mesh the position is the REMAP of the reference face, which `CurvView` does not carry.
- **The moving mask reaches only the sinks that re-read it.** `RunOutput::updateMask` (called at FRAME time, and by toggling the two bins' solid lists, so the cost is the surface not the volume) refreshes the PNG frames and the live shm planes. `<prefix>_mask.bin` and the web `static` mask are written ONCE by their own contract and hold the azimuth-0 body; making them time-dependent is a viewer-format change with a version bump, not a writer fix (`docs/viewer-format.md`).
- **`--rotor-frame mrf` is the frozen-rotor APPROXIMATION and says so everywhere.** Static azimuth-0 geometry, the SAME `u = ω×r` ghost image, and the rotating-frame equations (transport by `u − f·ω×r`, Coriolis `−fρω×u`, pressure work on the absolute u) inside a blended cylinder that the runner sizes off the measured swept bounds and REJECTS if it reaches within (band + 4) cells of a face. Three invariants: (1) the face transport correction is a CORNER STREAM POTENTIAL difference (`ψ = −ω f_a G(r)`, `G' = r f_r`) so the discrete transport divergence telescopes to zero — the pointwise `f·ω×r` form measured a 3e-2 velocity ring at the blend and was replaced, do not bring it back; (2) the surface tally passes the same `MrfView` as the rhs, so thrust/torque are the budget of the solved equations; (3) `stableDt` subtracts the frame velocity — the in-zone eigenvalues are `u_rel ± c`, and the absolute form under-counts by the tip speed exactly where the mesh is finest. MRF is exact only for axisymmetric outer conditions (`gpu_mrf` pins the quiescent spinning cylinder to the direct run at 1e-4); a crossflow rotor co-rotates its own far field — that is the approximation, warn before using it there. `--rotor-bins` is rejected with mrf; `rotor.bins == 1` and `Case::rotorMrf` is the switch. **MRF also runs on the O-grid** (`--ogrid --rotor-frame mrf`, z shaft only; moving geometry stays rejected — it would spin the mesh): `DeviceComp::setMrfCurv` builds the correction from a per-NODE stream potential (face flux = Δψ of the two in-plane corner nodes = exact `∮ψẑ·dl`, telescopes on any z-extruded mesh; at f = 1 over the wall it cancels the moving wall's normal flux exactly), the wall row mirrors about `ω×r` at the face midpoints (resting branch verbatim at ω = 0), and the tally adds the shaft moment on the same faces. Pinned in `gpu_mrf`: O-grid MRF torque vs Cartesian direct 0.22% (0.07% before the wall-acceleration pressure image of 2026-10-24 moved the Cartesian direct torque −0.14%; the O-grid torque did not move), node-psi transparency 6e-8.
- Not built yet: an on-disk table cache (rebuild is seconds to a minute, threaded), the incompressible branch, and `dns-ui` support — the editor's `Build` is a static snapshot with one `geo.cut`, so it can only ever show azimuth 0.

## DNS vs LES vs RANS labeling

The core scheme's only dissipation is physical ν; it is DNS iff the grid resolves the body BL (~D/√Re). `--les Cs` makes the field FILTERED — statistics depend on grid AND Cs by construction, and body dissipation carries model error (`cdf` uses ν only). If a run needed `--les` to survive, label it LES everywhere (reports, artifacts, memory) and state Cs AND the model (`--sgs smag|sigma`). σ-model (`--sgs sigma`, Cσ ≈ 1.35 — NOT a Smagorinsky Cs): νt from `dns/sgs.hpp`, zero in laminar shear / any 2D state, the transition-capable choice; validator rejects it at nz == 1. 2D + `--les` is a regularized 2D Euler: qualitative only.

A RANS field (`dns channel --rans`, `docs/rans.md`) is an ensemble-mean MODEL output, never a grounder. Label it `RANS SA-neg` / `RANS SST-2003m` / `RANS SST-Vm` plus the mode (`steady (local time stepping: pseudo-time, not time-accurate)` or `URANS (time-accurate)`) everywhere — reports, artifacts, memory. Invariants:
- **RANS off, and ν̃ ≡ 0 / k ≡ 0, is the DNS bit for bit** (`gpu_rans` G1/G2; HEAD-vs-branch stats byte compares). μt rides the LES `nut` slot; the ONE hot-kernel edit is `cmb.cr` → `cmb.crAt(c)`. `faceFlux`/`faceFluxCurv`/`kPrim`/`wall_ghost.hpp` stay untouched.
- **μt is written ODD across the wall ghost rows** (`kMutMirrorY`) → exactly 0.0 on the wall face; never computed from ghost scalars. Ghost scalars mirror the SPECIFIC value with the ghost's own density; SST ω is the image of TMR's 60ν/(β1 d1²).
- **Every `cmb.cr` consumer goes through `crAt(c)`**; additive hooks take the whole `StageCombine`. An additive term on the bare cr under LTS converges to lts·R + f = 0 — the wrong steady state (G7).
- **The residual is the explicit-mode extra stage** (ca = cb = 0, cr = 1, hooks in, scalar kernel in residual mode), never state differencing.
- **SA-neg is TMR SA-neg WITH ft2** — not SA-noft2 (TMR: incompatible). ν̃ is never clipped; SST's k/ω guard is COUNTED (`floorHits`), never silent.
- **Scalars convect first-order upwind on the mean mass flux** — the verbatim `faceFluxCurv` expression (G3 pins it to 0 ulp). The mean flow gets NO added dissipation; a stall is a user decision (U1), not a filter.
- **The per-cell diffusive dt is RANS-only**; DNS/LES `stableDt` is byte-identical (its global-extreme LES bound is over-conservative on clustered meshes — recorded, not fixed).
- **The FP32 steady march cannot certify convergence by residual** (measured): plain, it stalls where |R|·dt ≈ ulp(q)/2, resid ~1 on the M 0.2 channel vs 0.04 at the FP64 oracle state, and the slow ub mode sits under that floor while still 1.6% off. The solution does land on the oracle (G9). Pin the GPU against the oracle (`rans_channel1d`), not against a residual.
- **`--steady TOL` stops on the INTEGRALS, never the residual** (2026-10-25, `dns/steady_stop`): ub, bulk T, ∫ρν̃ | ∫ρk, ∫ρω each within TOL (relative) of a geometric extrapolation over the second half of the history, every window row monotone to 2^-20. Keep SEVERAL series: ub alone certifies TOL 1e-3 at 3400 iterations, 2.8% low (it dips, then rises on the slow mode); the companions hold it off. Keep the monotone-window check: four samples alias an oscillation (a damped one stopped 8.7× early without it). Monitor bulk T, not T − Tw (relative noise 5e-6 vs 3e-8). Measured stops Re_τ 180: TOL 1e-4 at 3.1–3.3e5 iterations, error 0.6–1.0 TOL vs the extrapolated fixed point. `steady_stop`, `gpu_runners`.
- **`--steady` marches a COMPENSATED state** (2026-10-25, `DeviceCompState::lo`): a Kahan low word per field, kernels read hi, every stage write goes through `gpu/internal/stage_write.hpp` (`stagePut`/`stageAdd`, increment form a + cb(b − a) + cr R, exact because ca == 1 − cb). Plain vs compensated is a COMPILE-TIME kernel switch (`withCompensation`) and must stay one: a runtime branch at the write changed the NSCBC kernel's FMA contraction and moved its bits. Any new StageCombine consumer writes through those helpers; any new state OVERWRITER on a compensated state must zero its cells' low words (the channel wall does). Measured: fixed point 2000× tighter (u drift 3e-8 vs 6e-5), plateau ~3.5× lower (0.35 vs 1.27), ub stops creeping, 1.13–1.15× per step at 64³ — but still ~10× above the 0.04 static floor, so the residual still cannot certify (docs/rans.md) — which is why the stop is on the integrals.
- **The O-grid far boundary is its own characteristic row, not NSCBC**: every `--nscbc-*` flag and `--pot` is rejected with `--ogrid` (they were silently ignored), Re > 800 only warns.

## Known gotchas

- **`offsetsAt` (gpu/index.hpp) takes indices with the same contract as `gidx`** — one cell out of range is legal and MUST wrap. The sparse boundary and surface-force kernels ask for the face at `j-1` with `j == 0`; computing offsets from `j == -1` instead of from the wrapped cell disagrees exactly at the wrap, which is where those kernels live. That produced a silent 0.4 freestream drift at the NSCBC corner rows and cost an afternoon.
- `dns bench` honours `--physics` (it used to parse it and then time the incompressible stepper regardless, which is why comp and incomp "measured" identically), and reports the VRAM THIS process allocates, not the card's total in use.
- Upstream "ripples" near bodies are trapped 6-12h dispersive standing waves, continuously forced by the SUB-CELL boundary layer — NOT staircase noise and NOT a start transient. Measured: `--cut-flux` ~20% (incomp only; comp variant diverges and is validator-blocked), `--penalize` ~15% (HALVES cdf — never for friction physics), `--ramp` quiet start ~0%. The only true cure is resolving the BL (D/√Re ≥ 3 cells); otherwise they are the honest footprint of under-resolution. Do not reach for filters/limiters — dissipation stays ν + explicit SGS.
- **Anisotropic cells break latent isotropy assumptions.** The ghost wall's deep-solid threshold (quiescent vs mirrored) is a physical DEPTH: it must follow the WIDEST local spacing, or the mirror band is under two cells thick along the wide axis, the interior stencil reads quiescent deep cells, and drag inverts (measured, `--focal` Re100 cylinder at fine-cell aspect 1.7: cd 1.49 → −7.6). Isotropic Cartesian grids hide this. Audit any other `min(hx,hy,hz)` used as "the" cell size before putting a body on a clustered mesh.
- **`--focal` plateaus are PHYSICAL (fixed 2026-10-23).** `Focal1D`'s a, b, w are REFERENCE coordinates; `flowFocal` used to hand it world bounds directly, so the physical fine region was [map(lo), map(hi)] -- ~R x narrower and pulled toward the box centre -- and a body "inside the plateau" sat on the blend/coarse cells (prop1c: blade 2 cells thick at h ~0.03 while the log claimed h_fine 0.0022). Now built with `Focal1D::fromPhysical`; containment, guard (3 h_fine) and the BL warning are physical; `test_focal` pins spacing = h_fine over body + guard on every axis. **Every pre-fix `--focal` result is invalid** (prop1/prop5/prop1c, the README rotor numbers) or flagged "regenerate before citing" (Re100/Re300 focal cylinder tables, front sat at up to 1.04 h_fine). The reference area qRef never passes through the map at all (`sampleCut` samples the world sdf on a uniform world lattice), so it was right before and after -- the old "it cancels" explanation was wrong. Fine cells now cost R x their width out of `--n`: the old prop flags (384x256x256, ratio 16, blend 1) are rejected for growth 1.33 > 1.25.
- **The ghost-wall tally is closed by construction** (fixed 2026-10-23, `gpu_comp_ghost_closure`). A solid cell in any fluid cell's flux stencil (face + edge neighbours) is ALWAYS a ghost, never deep; where its normal image is unusable (overlapping closed mesh parts: the nearest triangle is a buried face, the sample lands in solid) it is imaged from its fluid neighbours. Before, such cells were reset to rest at pInf: a resting wall at the wrong place and an open tallied surface (prop1c.stl at D/h 31-98: 2-5% of wetted faces missing, |sum nA|/A up to 2e-2, a spurious CT ~+0.025 on the prop). Normal-image cells are bit-identical; no anchor moved.
- **The incompressible ghost image reads a CLEAN trilinear cell** (fixed 2026-10-24, `gpu_tally_couette_torque`, `gpu_ghostfill`). `gpu/ghostfill` used to drop closed corners from the mirror point's interpolation cell and renormalize: that reads the field at the open corners' centroid, O(h) off, so ~5% of ghosts carried an O(1) wall-gradient error. Imposed circular Couette: the cut-cell friction tally PLATEAUED at +6% (convex) / +7-12% (concave) from R/h 13 to 64; spindown's profile error stalled (0.082% -> 0.073%, n 128 -> 256). Now the image moves out along the normal (1/16-cell steps, up to a cell diagonal) until its cell is clean and q_ghost = (sdf/d) q(image): imposed friction first order (-4.5/-2.4/-1.3% at R/h 16/32/64 -- the linear image misses the wall curvature, that is the scheme's order), the solver's steady friction -0.17/-0.048/-0.018%. Do not "fix" the remaining imposed-field first order with a quadratic image: its extrapolation weights reach ~7 and the ghost is no longer bounded by its samples. Unresolved spots (sub-cell gaps, concave corners) take a capped renormalized fallback (`fallbackCount()`, 0 on resolved convex bodies). Measured moves: `cyl_re60_n256_cd` 1.818636 -> 1.819749 (+0.06%, anchor 1.818652 kept, inside its 1%), its cdf 0.5730 -> 0.5653 (-1.3%); Re100 cd 1.7307 -> 1.7350; sphere Re300 n160 cd 0.7436 -> 0.7435; `val_mesh_sphere` mesh/analytic cd 0.6994/0.6869 -> 0.6798/0.6727 (gap 1.8% -> 1.05%). Spindown's profile error is now LARGER at n 128 (0.30% vs 0.08%) but converges (0.67/0.30/0.12% at n 64/128/256) where the old one stalled: the renormalization bias happened to cancel part of the concave wall's curvature error.
- **The compressible ghost image's `a` follows the sample it ACTUALLY reads** (fixed 2026-10-24, `gpu_comp_ghost_couette_exact`). `normalImage` drops solid corners of the sample's trilinear cell and renormalizes; the renormalized sample sits at the fluid cells' weighted wall distance sum(w phi)/sum(w), not at dsmp, so `a = dw/dsmp` was wrong by a grid-independent factor (+2.08% wall shear at dw = h/8; torque/heat tallies plateaued at ~1% Cartesian, ~2% and GROWING on focal). Dropped-corner ghosts now use the weighted distance; full stencils keep dw/dsmp bit-for-bit. Any wall-linear profile is exact.
- **The wall pressure image is the wall's momentum balance, `grad p|w = rho (f - a_wall)`** (fixed 2026-10-24, `gpu_tally_archimedes`, `gpu_tally_kutta_joukowski`, `gpu_rotor_comoving_fixed_point`). At a resting wall with no body force that IS the zero-gradient copy -- not an approximation, so resting walls are untouched. Rotor/MRF walls add the centripetal term (`p_g = p_s + rho_s a_wall.(x_s - x_g)`, the `aspan` table; `GhostWallMotion` returns `{u, a}`, `dns::rotorWallAcceleration`; O-grid `wallSpan`), conv plates the hydrostatic one (`p0 = p1 +- rho1 g hy`). rho and p are sampled ON the normal from an all-fluid stencil (a renormalized one drifts up to 0.2h off it, an O(h) dp/ds error); the adiabatic image keeps T. Co-rotating wall residual 1.1 -> 0.035 rho w^2 R; Archimedes/KJ closure second order. Do NOT replace the copy with a two-sample linear pressure extrapolation: with the dissipation-free central flux it has a growing wall mode (1D eigen-analysis, Re lambda 0.58 c/h). The normal viscous term n.div(tau) is deliberately omitted (pairs with the tangential term the linear velocity image drops at the same order). Moves: lens direct rotor torque -1.4%, `val_comp_cyl_re60` +0.004%, Re100 comp cd +0.10%. Imposed test states must be SOLUTIONS of the solved equations at the wall: a linear p at rest without a body force, or inviscid slip flow against a no-slip image, test nothing.
- **SSP-RK3 weights sum to exactly 1 in FP32** (fixed 2026-10-24, `gpu_mrf_conservation`). `Real(1/3) + Real(2/3)` is 1 + 3e-8, which inflated every conserved total ~2e-8 per step on any non-uniform field. Every GPU stepper forms `ca = Real(1) - cb` (exact by Sterbenz for cb >= 1/2). Never write the two rounded thirds again.
